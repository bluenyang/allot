### A-3 — 중간: 승인된 토큰 저장 동작을 축소하고 사전 승인 없이 진행

`0b8fc93`의 승인된 spec은 `account.create.before`와 `update.before`에서 토큰을 암호화해 저장한다고 정했다.

`0cbcbcc`는 이를 다음과 같이 바꿨다.

- 생성 시에만 암호화한다.
- 갱신 토큰은 버린다.
- 로그인 시 계정 갱신을 끈다.
- 갱신 방식은 0.1.7에서 정한다.

## 비판

### B-1 — 중간: 독립 변경을 묶는 커밋이 반복됨

### B-2 — 중간: 공휴일 동작의 지원 범위를 승인 없이 줄임

최초 승인 spec은 양력 연간 RRULE의 라이브러리 해석, 대체공휴일의 다음 영업일 탐색을 정했다. 다음 변경은 단순한 내부 계산 방식 교체를 넘는다.

- `195e90d`: `INTERVAL`·`SKIP` 거부, `BYMONTH` 필수화.
- `7d75afa`: 날짜 이동 최대 31일, 긴 연휴·대체일 탐색 한도.
- `a5fcf14`: 1990년 이전 규칙·날짜 제외.

이후 `1f92f33`, `eb13bf8`, `e20a07b`가 정정 메모를 추가·수정했다. 그러나 `approvals:`에는 해당 지원 범위 축소의 승인이 없다. `R/review/review-1.md`도 이를 PM의 조치로 기록한다.

리뷰어가 제안하거나 수정 결과를 확인한 것은 사용자 승인이 아니다. 기본 한국 세트의 결과가 유지됐다는 검증 역시 사용자 규칙의 지원 축소를 승인하지 않는다. 첫 감사 A-3과 같은 절차 문제다.

### B-3 — 중간: 생성 설정 파일을 정해진 변경 경로 밖에서 커밋

`.agents/harness/generated.yaml`은 `.claude/settings.json`을 생성 파일로 열거한다. `901c1d3`은 이 파일의 hooks와 permissions를 `chore` 커밋으로 변경했다.

따라서 이번 감사 기준의 **생성 파일 변경은 update/config 커밋이어야 한다**는 조건을 위반한다. `.gitignore` 변경까지 함께 담았다.

커밋 메시지의 “The user's settings”만으로 사용자가 직접 편집했는지, 에이전트에게 예외를 지시했는지 확인할 수 없다. 그러므로 에이전트가 자기 권한 파일을 직접 편집했다는 C3 위반까지 단정하지 않는다. 가드가 강화됐다는 코드 리뷰 결과도 변경 절차 준수를 대신하지 않는다.

Drizzle 산출물은 최초 감사의 사용자 처리에서 reins 생성물과 구별한 해석을 유지했다. 다만 실제 생성 명령의 실행은 Q-3으로 남긴다.

첫 감사 A-4의 사용자 처리에서는 준비 실패 시 즉시 멈추기로 했다. 이번 기록은 그 약속과 맞지 않는다.
