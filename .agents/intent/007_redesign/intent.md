## 바라는 결과
사용자 선택 (2026-11-15, 질문 답):

- 아직 없는 메뉴(AI 재무 › 명세서 분석·AI 어시스턴트, 설정 › AI·연동): **"숨김"**

풀어 쓰면 (PM 해석):
1. **외형**: 캔버스의 토큰(색·글꼴·크기·모서리·간격)과 컴포넌트(버튼·입력·배지·탭·표·모달)를 앱 전체에 적용한다. 셸은 사이드바 240px(개요 / 관리 / 설정 묶음, 아래에 사용자 이름과 역할)·페이지 헤더(경로, 제목, 설명, 주요 버튼)·푸터(버전, "데이터는 이 서버에만 저장됩니다", GitHub·변경 기록·문제 신고 링크).
2. **화면**: 캔버스에 있는 현황·구독(+추가 모달)은 캔버스대로, 캔버스에 없는 분배·일정·변경 내역·계정·관리·로그인은 같은 토큰과 컴포넌트로 맞춘다. 동작과 API는 그대로 둔다 — 데이터, 계산, 로그인·계정·관리 흐름이 지금과 같게 움직여야 한다.
3. **설정 › 테마** (계정마다 서버에 저장): 주 색상(5가지 + 직접 입력), 포인트 색상(4가지), 모서리(각지게·기본·부드럽게), 밀도(기본·촘촘하게), 라이트·다크 미리보기. 글자 대비가 4.5:1보다 낮아지는 색은 진하게 바꿔 쓴다(캔버스 문구).
4. **설정 › 일반** (계정마다 서버에 저장): 선호 테마(라이트·다크·시스템), 날짜 형식, 금액 단위(원·천원·만원 — 테마 탭의 "금액 표시"와 하나로), 음수 표기, 기준 일정(월급일·분배일·카드 결제일), 환율 직접 입력 + 버퍼, 주말·공휴일이면(앞 영업일 / 다음 영업일 / 그대로).
4-1. **공휴일 규칙 세트** (사용자 말: "약간 플러그인??? 형태로 두자. rrule로 된 규칙 세트를 이용한다는 느낌으로."): 공휴일은 코드가 아니라 규칙 세트(iCalendar의 `RRULE`·`RDATE`·`EXDATE`)로 정의한다. 기본 세트(한국 공휴일)를 함께 싣고, 사용자는 세트를 켜고 끄거나 직접 추가할 수 있다. 영업일 계산은 순수 함수로(주말 + 켜진 세트의 날짜).
5. 설정 탭: 일반 · 테마 · 로그인·보안(지금의 계정 화면을 옮김). AI·연동과 데이터 탭은 숨긴다.
6. 캔버스에 있지만 기능이 없는 것은 그리지 않는다: AI 분석 버튼과 명세서 카드, "마지막 동기화", API 문서 링크, 그 밖에 연결할 기능이 없는 버튼(spec에서 화면마다 목록으로).

## 제약
- 공개 저장소: 캔버스의 금액·이름·플랜 예시를 코드·테스트·커밋·캡처에 옮기지 않는다. 실제 데이터가 보이는 캡처는 커밋하지 않는다.
- 설정은 사용자 데이터처럼 `user_id` + RLS 아래에 둔다(0.1.1). 바꾸면 변경 내역에 남고 되돌릴 수 있게(캔버스 문구 "바꾼 설정은 변경 내역에 남고, 되돌릴 수 있어요") — 방식은 spec.
- 사용자가 고른 색도 대비 4.5:1(작은 글자)을 지킨다. 색만으로 구분하지 않는다.
- `calc.ts`는 순수하게 둔다. 표시 형식(날짜·금액 단위·음수)은 표시 쪽에서.
- 의존성은 정확한 버전, `minimumReleaseAge` 지킴. 개발·확인은 `docker/compose.dev.yaml`.
- E2E와 로그인·계정·관리 흐름 검사(0.1.2 V-n)가 리디자인 뒤에도 통과해야 한다.

## 열린 질문
1. ~~설정 › 일반 항목~~ → 답함(아래 "질의서 기록"). 넣음: 선호 테마, 날짜 형식, 금액 단위, 음수 표기, 기준 일정, 환율 직접 입력 + 버퍼, **주말·공휴일 처리(규칙 세트)**.
2. **음력 공휴일(설날·추석)과 대체공휴일**: rrule(RFC 5545)은 양력 반복만 표현한다(음력은 RFC 7529 RSCALE인데 JS `rrule` 2.8.1은 지원하지 않음). PM 제안: 기본 한국 규칙 세트는 양력 공휴일을 `RRULE`로, 음력·대체공휴일은 연도별 `RDATE` 목록(예: 올해부터 몇 해)으로 넣고, 목록이 끝나는 해에는 화면에 "공휴일 자료가 ○○년까지"라고 알린다. 대안: 음력 변환 표를 코드로 넣어 계산.
3. **주말·공휴일 조정을 어디에 적용할까?** PM 제안: 기준 일정(월급일·분배일·카드 결제일)과 그 날짜로 계산되는 현황의 결제 예정·분배 날짜. 구독마다의 다음 결제일에는 적용하지 않음(구독 결제는 서비스마다 규칙이 달라서).

### 에이전트가 정한 것
- **글꼴을 앱 안에 넣는다**(IBM Plex Sans KR·Mono를 패키지로 번들). 대안: 지금처럼 Google Fonts에서 받기. 이유: 금융 데이터를 다루는 셀프 호스팅 앱이 열 때마다 외부(Google)에 요청을 보내지 않게 — "보안과 개인정보가 기능보다 먼저".
- **휴대폰 폭에서는 지금의 아래 탭 막대를 유지**하고 모양만 새 토큰으로. 대안: 캔버스의 "좁은 화면에서는 위로 쌓여요". 이유: 0.1.9 모바일 앱(Capacitor)에서 아래 탭이 맞고, 지금 E2E·사용 습관이 그대로 간다.
- **편집 폼**: 캔버스 규칙("필드 6개 이하는 640px 모달, 많으면 새 페이지, 목록 안에 펼치지 않음")을 따르되 `EditSheet` + `useEditor` 구조는 유지하고 `EditSheet`를 모달로 바꾼다(AGENTS.md 규칙과 맞춤).
- 다크 모드는 유지한다(캔버스 테마 미리보기의 다크 값 사용, 나머지 다크 토큰은 spec에서 파생).
- **"플러그인" = 데이터인 규칙 세트**, 코드 플러그인(실행되는 JS)이 아니다. 대안: 코드를 불러오는 플러그인. 이유: 금융 데이터 앱에서 남이 만든 코드를 실행하지 않기 — 규칙 세트는 검증(zod)만 하면 안전하다. 세트 형식(JSON 안에 RRULE 문자열, 또는 .ics 일부)은 spec에서.
- 반복 규칙 해석은 `rrule` 2.8.1(npm, 의존성 tslib 하나, 2023년 이후 갱신 없음 — 안정판). 대안: 직접 작성. 이유: RFC 5545 해석을 새로 짜지 않기. 순수 계산이므로 `src/lib/` 쪽에 두고 서버도 쓴다.
- 사이드바 메뉴 이름은 캔버스대로(분배 → 월급 분배, 내역 → 변경 내역). 개발 메뉴는 지금처럼 남긴다(위치는 spec).

## 하지 않을 것

- 언어(→ 0.1.3), 시간대·기준 통화·함께 쓰는 외화(계산 변경, 미정), 환율 자동 갱신(로컬 로드맵 아이디어), 주 시작(하지 않음).
- 공휴일 조정 밖의 새 계산 기능(캔버스의 "고정 지출 추이" 같은 그래프가 지금 데이터로 그릴 수 없으면 spec에서 빼거나 대체를 묻는다).
- API·계산 동작 변경 — 설정 저장, 규칙 세트, 주말·공휴일 조정을 위한 추가만. 조정을 "그대로"로 두면 지금 계산과 같아야 한다.
