### 저장 (S-7, S-8, S-9, W-4)
- 새 표 `preference`(사용자당 1행, `user_id` PK, `userScoped` RLS·FORCE):
  - `theme_mode`: `system`/`light`/`dark`, 기본 `system`.
  - `primary`·`accent`: `#RRGGBB` 문자열, null = 기본(#14705A / #E0670E).
  - `radius`: `sharp`/`base`/`soft`, 기본 `base`.
  - `density`: `base`/`compact`, 기본 `base`.
  - `date_format`: `iso`/`dot`/`us`, 기본 `iso`.
  - `amount_unit`: `won`/`thousand`/`man`, 기본 `won`.
  - `negative`: `minus`/`paren`/`red`, 기본 `minus`.
  - 열거형은 pg enum이 아니라 `text` + zod다. 값을 늘릴 때 마이그레이션이 가볍다.
- `settings`에 `day_shift`: `none`/`before`/`after`, 기본 `none`. 지금 사용자는 마이그레이션으로 `none`이 되어 계산이 지금과 같다.
- 새 표 `holiday_set`(`user_id` + `id`, RLS·FORCE): `name`, `enabled`, `builtin`(`kr` 또는 null), `rules`(jsonb, 사용자 세트만).
  - 기본 세트의 규칙은 코드(`src/data/holidays-kr.ts`)에 있다. 그래서 앱이 갱신되면 기본 세트 규칙도 함께 갱신된다. 행에는 켬/끔만 저장한다.
  - 기본 세트의 행이 없으면 켜진 것으로 본다.
- API:
  - `PUT /api/preferences`(전체 교체, zod).
  - `GET/POST/PUT/DELETE /api/holiday-sets`(기존 목록 자원과 같은 모양).
  - `PUT /api/settings`의 zod에 `dayShift`를 더한다.
  - `/api/state`가 `preferences`와 `holidaySets`를 더해 돌려준다. 행이 없으면 기본값이다.
- zod 규칙:
  - 색은 `^#[0-9A-Fa-f]{6}$`.
  - 세트 이름은 1~40자, 규칙은 1~100개.
  - 규칙 하나는 `{ name 1~40자, rrule?, rdate?: date[], exdate?: date[], substitute?: { on: ('SA'|'SU')[], since?: 연도 } }`이고, `rrule`이나 `rdate` 중 하나는 있어야 한다.
  - `rrule`은 `FREQ=YEARLY`만 받는다. `RSCALE`는 없거나 `GREGORIAN`이나 `DANGI`다. 그 밖의 값은 400이다(조용한 양력 계산 방지, 0.1.2 PM 확인 참고).
  - `DANGI`는 `BYMONTH`(1~12, 윤달 `L` 없음)·`BYMONTHDAY`(1~30, 음수 -1~-2)만 받는다.
  - 파싱은 `rrule-temporal`로 한 번 해 보고, 실패하면 400이다.
- 세 표 모두 `OWNED`에 넣는다. 그러면 변경 내역 기록, 되돌리기, 계정 데이터 옮기기(`moveOwner`), 관리자 완전 삭제가 그대로 따라온다. 완전 삭제의 "데이터 표 12개"가 14개가 된다.

### 공휴일과 영업일 (S-9, S-10, W-5)
- `src/lib/holidays.ts`(순수, 서버도 import 가능):
  - `holidaysIn(sets, fromYmd, toYmd) → { date, name, setId, substitute: boolean }[]`.
  - 양력 규칙은 `rrule-temporal`의 `between`으로 푼다.
  - `RSCALE=DANGI` 규칙은 우리가 푼다. 연도마다 `Temporal.PlainDate.from({ calendar: 'dangi', year, monthCode, day })`를 ISO로 바꾼다. 음수 일(-1)은 그 달 일수에서 센다. 윤달(`M05L`)은 받지 않는다(검증에서 400).
  - `Temporal`은 늘 `temporal-polyfill/full`에서 가져온다. 런타임마다 결과가 달라지지 않게 하기 위해서다(rrule-temporal도 같은 이유로 polyfill을 쓴다).
  - 대체공휴일: `substitute.on`의 요일(`since` 연도부터)에 걸리거나 다른 공휴일과 겹치면, 그 뒤 첫 비공휴일 평일이 대체공휴일이다. 연휴(설·추석 3일)는 묶음으로 본다. 묶음 안의 날이 일요일이면 묶음이 끝난 다음 첫 평일이다.
- `src/data/holidays-kr.ts`(공개 정보인 법정 공휴일만):
  - 신정 1/1.
  - 설날 전날·당일·다음날: DANGI 12/-1, 1/1, 1/2, 대체 SU, since 2014.
  - 삼일절 3/1: SA·SU, since 2021.
  - 어린이날 5/5: SA·SU, since 2014.
  - 부처님오신날: DANGI 4/8, SA·SU, since 2023.
  - 현충일 6/6: 대체 없음.
  - 광복절 8/15: SA·SU, since 2021.
  - 추석 전날·당일·다음날: DANGI 8/14~16, SU, since 2014.
  - 개천절 10/3: SA·SU, since 2021.
  - 한글날 10/9: SA·SU, since 2021.
  - 성탄절 12/25: SA·SU, since 2023.
  - 선거일·임시공휴일은 규칙이 없다. 사용자가 자기 세트에 `rdate`로 더한다(설정 화면 안내 문구).
  - 정확한 법 조항과 연도는 W-5에서 「관공서의 공휴일에 관한 규정」으로 확인하고 파일 머리 주석에 출처를 적는다.
- `calc.ts`에 순수 함수 `monthDates(ym, settings, holidayDates) → { pay, transfer, billing }`를 둔다.
  - 각 값은 `{ nominal: Date, date: Date, shifted: 'before'|'after'|null }`이다.
  - 31일은 그 달 마지막 날로 바꾼 뒤 조정한다.
  - `none`이면 `date = nominal`이다.
  - `calc.ts`는 `holidays.ts`를 부르지 않는다. 휴일 날짜 집합을 인자로 받는다. 그래서 `calc.ts`는 의존성을 늘리지 않는다.

- 정정 메모(리뷰 1~3, 2026-11-15): 결과가 조회 범위에 따라 달라지지 않게 했다. 공휴일은 늘 1990-01-01부터 최소 2060년까지 계산해 규칙 세트마다 캐시하고, 거기서 범위를 꺼낸다(대체공휴일이 이웃 연휴로 줄줄이 밀릴 수 있어서). 1990년 이전의 규칙·날짜는 쓰지 않는다(그 이전을 물으면 공휴일 없음). 그 밖의 한도: 날짜 조정은 최대 31일(`SHIFT_LIMIT`). 그 안에 영업일이 없으면 원래 날에 "옮길 영업일 없음"이라고 표시한다. 대체공휴일은 31일을 넘는 연휴에는 생기지 않고(`MAX_RUN`), 연휴 끝에서 31일 안에서만 찾는다. 양력 규칙은 `INTERVAL`·`SKIP`을 받지 않고 `BYMONTH`가 있어야 하며, 기준일은 1900-01-01로 고정한다. 기본 세트(한국 공휴일)의 결과는 바뀌지 않는다.

- 헤더: 관리 / 구독, 설명, "구독 추가" 버튼.
- KPI 4개: 월 환산 합계, 연 환산 합계(×12), 영수증 미확인(활성 중 `verified=false` 수), 적용 환율(`fxRate`)과 아래 "버퍼 n%".
- 탭: 목록·월별 미리보기·플랜 전환은 지금 그대로다. 캔버스의 상태 탭(전체·활성·회사 지원·해지 + 개수)은 목록 탭 안의 상태 거르개(분절 버튼)로 둔다. 탭이 두 줄이 되지 않게 하려는 것이다(PM 결정, 대안: 상태를 위쪽 탭으로).
- 분류·결제 경로 선택 상자, "n개 · 다음 결제일 순".
- 표 열: 서비스(+플랜), 분류, 주기, 청구 금액(원래 통화, USD는 "USD 20.00 +10%"), 월 환산, 다음 결제, 결제 경로, 영수증(확인됨/미확인 배지). 행을 누르면(Enter 포함) 편집 모달이 열린다.

  - 설명 문구 "저장하면 서버에 먼저 기록되고 변경 내역에 남아요."
  - 상태(활성/해지/회사)는 지금처럼 편집 모달에 있다.

  - 저장 전까지는 미리보기 칸에만 적용한다.
  - "기본값으로" 버튼이 있다.
  - 대비 보정 안내 문구가 있다. 보정이 일어나면 "글자용으로 #xxxxxx을 써요"라고 실제 값을 보인다.
- 로그인·보안: 지금 `Account.vue`를 그대로 옮긴다(내용과 동작 동일).
- **월급 분배**의 설정 칸에서 월급일·분배일·카드 결제일·환율·버퍼를 빼고 "설정 › 일반에서 바꿔요" 링크를 둔다. 실수령·구독 이체 올림 단위는 남는다.

**나머지**(분배, 변경 내역, 관리, 로그인, 개발): 토큰·표·배지·탭·모달만 적용한다. 로그인은 가운데 카드(브랜드, 방식 버튼, 비밀번호 폼)다.

## 우려
- 번들 크기: 한국어 글꼴, Temporal polyfill(full), FullCalendar.
  - 글꼴은 `@fontsource`의 unicode-range 조각이라 쓰는 글자만 받는다.
  - 달력은 동적 import로 나눈다.
  - polyfill은 `holidays.ts`를 쓰는 화면(현황 헤더, 일정, 설정)에서 필요하다. 첫 화면에 들어가므로 V-1에서 크기를 잰다.
- `rrule-temporal` 2.2.9는 2026-11-13에 나온 새 판이다(자주 갱신된다). 정확한 버전으로 고정하고, 음력은 우리 코드가 푼다. 그래서 라이브러리 변화의 영향이 양력 규칙에만 미친다.
- ICU의 `dangi` 계산은 2050년까지 천문연구원 자료와 맞음을 확인했다(intent 기록). 2051년 이후는 확인 자료가 없다. 세트 미리보기에 "음력 날짜는 2050년까지 대조했어요"라고 적는다.
- 대체공휴일 규정은 바뀔 수 있다(2021, 2023 개정). `since`로 연도를 나눠 표현한다. 새 개정은 앱 갱신으로 기본 세트에 넣는다.
- `--accent`의 뜻이 바뀐다(초록 → 주황). W-1에서 기존 사용처를 남김없이 옮기지 않으면 주황 버튼이 생긴다. W-1 리뷰 때 `grep var(--accent` 결과를 붙인다.
- E2E 선택자가 많이 흔들린다. 라벨과 ARIA 이름을 유지하는 것이 원칙이고, 바뀌는 것은 메뉴 이름 둘, 현황 탭 이름 하나(다가오는 변경 → 예정), 설정 칸 위치다.
- 0.1.2 감사는 dad7b58까지다. 이 작업을 머지한 뒤 rc.1 전에 감사를 보충해야 한다(intent 계획 4).
