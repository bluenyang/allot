`docs/ROADMAP.md` 0.1.5 줄: 일회성 지출 — 일시불, 나눠 내기, 할부.

사용자 말:
> 기능: 단발 지출(일시불·분할납부·할부) 관리. "가계부까지는 아님" (2026-11-11, `.loctx/ROADMAP.local.md`)
> v0.1.5 작업 파악. 기획 상황 파악하여 0.1.6까지 미리 기획 한 다음, 0.1.5 루프 시작 예정 (2026-11-21)
> 캔버스를 업데이트 하였음. 버퍼에서 지출하는 기능(v0.1.6에서 추가될 예정)도 포함되어 있음. 참고하여 다시 계획해봐 (2026-11-21)

지금 Allot은 매달 같은 금액이 나가는 구독만 다룬다. 노트북처럼 한 번 사는 물건이나 몇 달에 걸쳐 나가는 할부는 입력할 곳이 없다. 그래서 그 달 급여 통장에 실제로 남는 돈(나머지)과 구독 통장에 보낼 돈이 맞지 않는다. 화면의 "기록 추가 › 일회성 지출"은 '준비 중'이다(`src/components/AddRecordModal.vue`).

## 바라는 결과
기준은 디자인 캔버스 "지출" 보드(AppSubs, 버전 1795255777-33ed)다. 사본은 이 세션 scratchpad에 있고, spec 때 `.loctx/reports/0.1.5/canvas/`로 옮긴다. 아래는 PM이 보드를 읽고 정리한 것이다.

1. **메뉴 "지출"**: 예산의 "구독"이 "지출"이 된다. 탭은 **일반 · 할부 · 구독** 세 개이고, 탭마다 추가 버튼(지출 추가 / 할부 추가 / 구독 추가)이 있다. 구독 탭은 지금 구독 화면 그대로다(목록, 전환 미리보기, 변경 일정, 이체액 계산).
2. **이번 달 지출 반영 카드**(세 탭 공통, 위쪽): 계산 규칙은 사용자가 고른 "결제 수단별 반영"이다.
   - 나머지에서 빠지는 돈: 일반과 할부로 나눠 보여 준다.
   - 구독 이체에 더하는 돈: 구독 통장 이체가 바뀌기 전과 후의 값을 보여 준다.
   - 그 달 나머지: 음수면 "모자라요"를 띄우고 "월급 분배에서 조정 →"으로 이어 준다. 다른 금액은 자동으로 바꾸지 않는다.
   - 카드는 청구일이 속한 달에 반영한다.
3. **일반 탭(일시불)**:
   - 목록 열: 내용·메모, 분류, 결제일, 금액(원래 통화), 원화, 결제 수단, 반영(달과 어디서 빠지는지), 상태
   - 상태: 예정, 청구 예정, 냄, 취소(반영 안 함)
   - 거르기: 상태, 결제 수단, 분류
   - KPI 3개: 이번 달 일반 지출, 다가오는 지출, 결제 수단별
   - 휴대폰에서는 카드 목록으로 보여 준다.
4. **할부 탭(카드 할부 · 나눠 내기)**:
   - 왼쪽 목록에서 고르면 오른쪽에 상세가 나온다. 목록은 진행 중 / 완료 / 전체로 거르고, 진행률과 다음 회차를 보여 준다.
   - 상세: 총액, 회당, 낸 금액, 남은 금액, 결제 수단, 반영, 그리고 회차 표(회차, 청구일, 금액, "고침" 표시, 반영 달, 상태 냄/다음/남음, 수정)
   - 동작: 수정, **중도 완납**, 취소
   - KPI 3개: 진행 중 남은 금액, 달마다 나가는 회차(막대), 할부 수수료
5. **추가·수정 창 3단계**:
   - 1단계 "무엇을 샀나요": 내용, 금액(KRW/USD), 결제일, 적용 환율(구독과 같은 환율과 버퍼), 원화 환산, 분류(생활·가전·여행·경조사·의료·보험·기타 직접 입력)
   - 2단계 "내는 방식": 일시불 / 카드 할부 / 나눠 내기 / 버퍼 사용(0.1.6)
     - 카드 할부: 3·6·12개월 또는 직접 입력, 무이자/유이자. 유이자면 카드사가 안내한 수수료 합계를 적는다.
     - 나눠 내기: 2·3·4회 또는 직접 입력, 간격(매달 같은 날 / 2주마다 / 날짜 직접 정하기)
     - 결제 수단: 카드 · 매달 N일 청구 / 급여 통장 / 구독 통장
     - 첫 청구일(나눠 내기는 1회차 날짜)
   - 3단계 "회차 확인": 회차 요약, 회당 금액, 회차 목록, 반영, 메모
   - **회차 수정 창**: 청구일, 금액(이 회차만 바뀜), 상태(남음/냄)
6. **계산 규칙**(캔버스 예시 기준, PM 해석):
   - 회당 금액은 (원금 + 수수료) ÷ 회차 수를 10원 단위로 내림한 값이고, 끝전은 마지막 회차가 받는다.
   - 카드는 결제일 다음 달의 카드 결제일에 청구된다(11/18 구입 → 12/16). 청구일은 저장한 뒤에도 고칠 수 있다.
   - 한 회차를 고쳐도 다른 회차는 그대로다. 총액과 다르면 목록에 차이를 보여 준다.
7. **기록과 AI**:
   - 다른 데이터처럼 변경 묶음에 남고 되돌릴 수 있다.
   - MCP에 읽기 도구와 쓰기 도구를 더하고, 쓰기는 0.1.4의 제안 → 확인 흐름을 탄다.
   - 제안 미리보기에는 그 달 나머지와 구독 이체의 전후를 넣는다.

## 제약
- 지금 받는 입력은 그대로 받는다. 구독 화면을 "지출 › 구독" 탭으로 옮겨도 구독의 필드·편집기·플랜 전환·보기 4개는 그대로 두고, 예전 주소는 새 주소로 이어 준다. 커밋 전에 `git show <base>:<file>`로 비교하고, 옛 값을 저장했다 다시 읽는 E2E를 둔다(AGENTS.md).
- 일회성 지출이 없는 사용자는 분배·이체 숫자가 지금과 한 원도 다르지 않아야 한다.
- `calc.ts`는 순수 함수로 둔다. 모든 쓰기는 RLS 아래에서 화면과 같은 규칙(검증·변경 묶음)을 거친다.
- 공개 저장소다. 예시·테스트에 실제 데이터를 쓰지 않는다. 캔버스 예시 이름(노트북, 에어컨 등)은 가짜 데이터라 테스트에 써도 된다.
- "가계부까지는 아님": 카드 사용 내역 전부를 적는 기능이 아니다. 미리 정해 둔 지출만 다룬다.

### 에이전트가 정한 것
- **지출 1건 + 회차 행**: 회차를 계산해서 행으로 저장한다(대안: 저장 없이 매번 계산). 이유: 회차별 금액·날짜 수정과 상태를 남기려면 행이 있어야 한다. 처음 만들 때 calc가 회차를 채우고, 사용자가 고친 회차는 "고침" 표시와 함께 그대로 둔다. 일시불도 회차 1개짜리 같은 모양이다.
- **0.1.5의 "버퍼 사용"은 '준비 중'**: 2단계의 내는 방식 버튼과 할부 탭 거르기에 보이되 누를 수 없다(0.1.4 rc.2 규칙 "비활성화 해두고 '준비중' 표기해놓자"). 데이터 모양은 0.1.6에서 방식 하나(버퍼 통장, 채울 개월)를 더할 수 있게 둔다.
- **나머지는 자동으로 어디에도 보내지 않는다**: 음수면 경고만 띄운다. 근거는 캔버스 문구 "다른 금액은 자동으로 바꾸지 않아요"와 사용자 말 "사람이 그걸 정하게 해야지 뭔 자동으로 보내"(2026-11-18).
- **"냄"은 사람이 표시**: 캔버스 문구 "냄 표시는 직접 해요. 카드 명세서와 자동으로 맞추는 기능은 나중에 붙어요." 자동 대조는 0.1.7이다. 취소하면 남은 회차가 계산에서 빠지고, 이미 낸 회차는 남는다.
- **CSV 내보내기 버튼**: 다른 화면의 내보내기와 같이 '준비 중'으로 둔다.
