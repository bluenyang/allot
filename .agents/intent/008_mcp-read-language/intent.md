지금 Allot은 브라우저 로그인으로만 데이터를 볼 수 있다. AI 클라이언트(Claude Code·Desktop 등)가 인터넷 너머에서 사용자의 데이터를 읽을 길이 없고, 화면은 한국어로만 나온다.

## 바라는 결과
PM 해석:
1. **API 키**: 사용자가 자기 계정의 키를 만든다 — 이름, 범위(0.1.3은 읽기만), 만료일(만료 없는 키는 설정 ON일 때만, OFF면 최대 1년). 키 원문은 만들 때 한 번만 보이고, 서버에는 해시만 남는다. 목록에서 마지막 사용 시각을 보고 언제든 폐기한다. 키는 그 사용자 데이터에만 닿는다(0.1.1의 `user_id` + RLS 그대로).
2. **키 관리 화면**: 설정 › AI·연동 탭(0.1.2에서 숨긴 탭, 캔버스 "설정 AI 연동")을 연다 — 이번에는 MCP 키와 연결 방법 안내만. LLM 키 등 기능이 없는 부분은 그리지 않는다.
3. **MCP 서버**: 같은 이미지·같은 포트의 HTTP 경로(Streamable HTTP)로, `Authorization: Bearer <키>`로 인증한다. 읽기 도구는 사용자가 화면에서 보는 데이터 — 월급 분배, 구독·결제, 일정(조정된 날짜 포함), 플랜 전환 예약, 변경 내역, 이번 달 현황 계산 결과(`calc.ts`). 쓰기 도구는 없다(0.1.4).
4. **화면 언어**: 설정 › 일반에 언어(한국어·English). 계정마다 서버에 저장, 로그인 전 화면은 브라우저 언어를 따른다.
5. **함께 싣는 것**: esbuild 보안 수정(GHSA-67mh-4wv8-2f99, 6937d61, master에 있음)과 게이트 갱신(69c53b9, 7572d85) — CHANGELOG에 적는다.

- `calc.ts` 순수 유지. 개발·확인은 `docker/compose.dev.yaml`.

### 에이전트가 정한 것
- **키는 Better Auth의 API 키 플러그인 위에서 만든다**(AGENTS.md: "Login and access features are Better Auth plugins on `server/auth.ts`"). 대안: 직접 테이블·해시 구현. 이유: 해시·만료·속도 제한·폐기가 이미 있고 프로젝트 규칙과 맞다. 플러그인이 RLS·`user_id` 구조와 맞지 않으면 spec에서 대안을 적는다.
- **MCP는 같은 서버의 경로로**(별도 컨테이너 아님). 이유: 0.1.x 결정 "One image serves the front end and the API"; 인증·RLS·조회 코드를 그대로 쓴다.
- **도구는 기존 조회 로직을 다시 쓴다**(새 쿼리를 따로 만들지 않음). 이유: 화면과 AI가 같은 숫자를 보게.
- **만료 없는 키 설정은 서버 전체 설정**(관리자 메뉴, 0.1.2의 로그인 제공자 ON/OFF처럼 env로도), 기본 OFF. OFF: 만료일 필수, 기본 90일, 최대 1년. ON: 사용자가 "만료 없음"을 고를 수 있다. ON→OFF로 바뀌면 이미 있는 만료 없는 키는 그때부터 1년 뒤 만료(spec에서 확정). 대안: 계정마다 사용자가 켜고 끔. 이유: 인터넷에 노출된 서버의 보안 기본값은 운영자가 정하는 것이 맞다(PM 해석 — 사용자 말에는 누가 켜는지가 없음).
- **키 범위 값은 지금부터 읽기·쓰기로 나눠 둔다**(0.1.3은 읽기만 발급). 이유: 0.1.4에서 키 형식을 바꾸지 않게.
