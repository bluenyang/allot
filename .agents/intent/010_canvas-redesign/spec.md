## 우려
- 크기: 화면 전부를 바꾸는 일이라 W-4~W-8 각각이 크다. 단위마다 리뷰를 받고 넘어간다(한 번에 몰아서 리뷰하지 않음).
- 캔버스는 지어낸 데이터로 그려져 있어, 빈 상태·긴 이름·많은 행·오류 상태는 그려지지 않은 곳이 있다(보고서 ND·Could not determine). 그려지지 않은 상태는 지금 동작을 새 컴포넌트 모양으로 유지한다.
- "이번 달 투자"·"투자 계좌"를 나머지 대상 이름으로 바꿔 보이는 것(S-6, S-9)은 PM 해석이다. 사용자 말("나머지는 투자가 아니거든?")과 캔버스 문구가 부딪쳐서 데이터 이름을 쓰는 쪽을 골랐다.
- 나머지 대상이 없을 때 나머지 나누기 행이 남는다. 화면에서 보이게 두어 데이터를 잃지 않지만, 쓰이지 않는 값이 남는다. 새 예산 방식(0.1.6 쪽)에서 정리.
- 다크 팔레트 공식을 바꾸면 사용자가 고른 색의 다크 값이 달라진다(저장값은 색 하나라 데이터 변경은 없음). 대비 검사로 막는다.
- 첫 화면 JS 30kB 한도는 PM이 정했다(새 컴포넌트·셸 때문에 009의 15kB보다 넉넉히). 넘으면 묻는다.
