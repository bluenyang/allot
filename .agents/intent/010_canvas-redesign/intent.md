## 문제
0.1.4-rc.1 확인 중 사용자가 폼 배치를 지적했고, 그것이 Claude Design 캔버스 "Allot Redesign"으로 앱 전체를 다시 그리는 일로 커졌다. 캔버스는 intent 009(MCP 쓰기) 범위 밖이라 같은 0.1.4 안에 이 intent를 따로 둔다. 결과물은 0.1.4-rc.2.

사용자 말:
> 캔버스대로 한 다음에는 프로젝트 내에서 알아서 개선/수정할 거거든? 캔버스 기준으로 디자인시스템(DESIGN.md)도 만들어두고, cavas 내의 디자인 시스템 페이지를 어떤 형태(md/html/코드 등등)로든 남겨주면 됨. (2026-11-18)
> 비활성화 해두고 '준비중' 표기해놓자. (2026-11-18, 기능 없는 캔버스 항목)
> 나는 나머지는 투자가 아니거든? … 나는 생활/구독/저축/투자 이런 식으로 아예 메뉴를 나누려고. (2026-11-18)
> UI 및 기능 개편(v0.1.4-rc.2) 진행. intent 부터 (2026-11-19)

지금 앱은 0.1.0~0.1.4의 화면이 조금씩 덧붙은 모양이고, 폼이 2열·제각각이며, 휴대폰 모양이 따로 없다. 캔버스는 화면 전부(라이트·다크·휴대폰)와 디자인 시스템(Foundations)을 새로 정했다.

## 바라는 결과
PM 해석:
1. **캔버스 기준의 앱**: 현황, 구독, 월급 분배, 일정, 대기 중인 변경, 변경 내역, 설정, 관리, 로그인이 캔버스(최신 1795018444-7b61) 모양이 된다 — 데스크톱·휴대폰·라이트·다크.
2. **디자인 시스템이 저장소에 남는다**: `DESIGN.md`(토큰·다크 팔레트 규칙·컴포넌트·문구 규칙)와 `docs/design/`의 Foundations 라이트·다크(값이 풀린 정적 HTML). 이후 개선은 이것을 기준으로 한다.
3. **기능 없는 캔버스 항목은 비활성 + "준비 중"**: 생활·저축·투자 화면, 명세서 분석, AI 어시스턴트, AI 모델(내 API 키), 키 관리의 이름 변경·범위 변경·연장·사용 기록·연결된 앱, 전역 검색, 알림, 내보내기, 일회성 지출, 대상↔통장 연결, 기준 통화·추가 외화·자동 환율·시간대, 일정별 개별 조정·일정 추가, 비밀번호 정책·자동 생성, 일정 시기 "직접 입력"·연도 넘는 기간.
4. **지금 기능으로 조금 더하는 것**(사용자가 정함, 원문은 `.loctx/ROADMAP.local.md`):
   - 구독: 수정·삭제·해지 모달, 추가·플랜 전환 2단계(VAT·상태·"그대로" 유지).
   - 월급 분배: 새 모양, 구간 기호 → 자동 N단계(저장값 유지), 올림 단위 1만/5만/10만 + "끄기"(1원으로 저장, 스키마 변경 없음), **"나머지" 대상 규칙(꼭 하나·못 지움)을 풂** → 없으면 남는 돈은 "급여 통장에 남음"으로 표시. 나머지 나누기 데이터·편집은 그대로.
   - 현황: "이번 달 투자"(지금의 나머지 나누기를 알약으로) + "나머지 ₩… 급여 통장에" 줄.
   - 대기 중인 변경: AI 제안 탭, "이체 후 남는 금액"(D-9: 이번 이체일~다음 이체 전날), 필요 이체액은 실제 계산값(D-8, 올림 후).
   - 일정: 목록 카드, 달력 머리줄, 이웃 달 주말도 파랑/빨강을 흐리게(D-2), 휴대폰 달 이동(D-3, "오늘" 버튼은 나중).
   - 변경 내역: 날짜 묶음, 행위자, 되돌리기 모달(되돌린 변경 다시 되돌리기 유지, D-10).
   - 셸: 사이드바 묶음(예산·AI), 헤더 테마 버튼 제거(설정에서만), 개발 메뉴 제거(`#dev`만), 본문 가운데 정렬, 휴대폰 위 막대·아래 5칸·더보기 시트(D-4).

## 제약
- 캔버스가 기준. 캔버스와 다르게 만드는 것은 사용자 결정(D-n)이 있는 곳만.
- **입력을 새로 거부하는 변경은 하지 않는다**; 생기면 커밋 전에 사용자에게(AGENTS.md). 기능을 빼는 변경(REMOVES-CAPABILITY)도 같이 묻는다. "나머지" 규칙 풀기는 더 받는 쪽이라 해당 없음.
- 스키마 변경은 없게(올림 끄기 = 1원). 생기면 `pnpm db:generate` + `pnpm check:migrations`.
- `calc.ts`는 순수하게. 공개 저장소: 캔버스 URL·실제 데이터는 저장소에 넣지 않는다(캔버스는 이름만).
- 다크 주황 배지 글자는 대비 때문에 어두운 색(D-10). 대비 검사를 디자인 시스템 단계에 둔다.

### 에이전트가 정한 것 (사용자에게 보였고 이의 없음)
- 대기 중인 변경 만료 문구(화면 24시간·대화 15분), 제안 제목 = AI 메모가 없으면 요약, 처리한 제안 건수 숫자 생략, 키별 "쓰기 제안 n건"(전체 기간).
- 표시 형식은 고르면 바로 저장. 관리자 계정 비밀번호를 비우면 외부 로그인만. 통장 역할 칩 + 직접 입력·들어오는 돈 칸 유지. 부채 상환 방식 기본 원리금 균등. OIDC 콜백은 앱 값(`/api/auth/callback/oidc`).
- `docs/design/` 형식: Foundations 라이트·다크를 값이 풀린 정적 HTML로. 대안: md 표만. 이유: 캔버스 페이지를 보이는 그대로 남기라는 사용자 말에 가장 가깝다.
- 이 작업은 0.1.4 안의 rc.2로 낸다(새 버전 아님). 이유: 사용자가 "v0.1.4-rc.2"로 불렀고, rc.1 확인에서 나온 일이다.
