## 바라는 결과
- **세 AI에서 OAuth로 연결**: 사용자가 Allot 주소를 넣고, Allot 로그인과 동의 화면을 거쳐 연결한다. 키는 붙여 넣지 않는다.
  - Claude: claude.ai와 휴대폰 앱(사용자 지정 커넥터), Claude Code.
  - ChatGPT: chatgpt.com의 사용자 지정 MCP 서버, Codex.
  - Gemini: Gemini CLI. Gemini 앱의 사용자 지정 앱은 지금 미국·영어·만 18세 이상 개인 계정만 쓸 수 있어 사용자가 확인할 수 없다(조사). 표준대로 맞추되 확인은 하지 않는다.
- **세 AI의 설치 묶음**: 같은 스킬 묶음을 세 AI가 함께 쓴다.
  - Claude Code 플러그인: 이 저장소를 마켓플레이스로 둔다.
  - Codex 플러그인.
  - Gemini CLI 확장(설치는 이 저장소 주소로).
  - claude.ai는 스킬을 ZIP으로 올린다.
- **스킬** (사용자가 고른 7개, 지금 있는 MCP 도구로만 동작):
  - 월초 점검
  - 급여 정산
  - 월말 정산(기타 소비, 통장 잔고 파악)
  - 구독 최적화 제안
  - 영수증 분석(나중의 분석 기능에서도 씀)
  - 소비·지출 계획
  - 자산관리
- **`/mcp` 주소**: MCP 주소를 `/mcp`로 한다. 지금의 `/api/mcp`는 API 키용 별칭으로 남겨 이미 연결된 키가 그대로 동작한다.
- **연결된 앱 관리**: 설정 › AI·연동에서 연결된 앱을 보고 끊는다. 끊으면 바로 401이 된다. '준비 중' 표시는 없어진다.
- **권한은 키와 같다**: OAuth로 연결해도 읽기 또는 쓰기 제안, 확인 방식, 키 주인의 데이터만 보는 범위가 API 키와 똑같다. 동의 화면에서 고른다.
- **패스키 로그인**: 로그인 방식에 패스키를 하나 더한다. 기본은 꺼짐이고, 로그인한 사용자가 자기 계정에 등록한다. 가입 경로는 아니다.

## 계획
(PM의 순서, 각 단계는 spec의 W-n이 됨)
1. **의존성**: `@better-auth/mcp`, `@better-auth/oauth-provider`, `@better-auth/cimd`, `@better-auth/passkey`를 1.7.18로 맞춘다. Better Auth 1.7에서는 예전 `mcp()`·`oidcProvider()`가 빠졌다(설치본에서 확인).
   - 조사에 따르면 `@better-auth/mcp`가 `oauth-provider ^1.7.18`을 끌어와 1.7.27로 풀릴 수 있다. Better Auth 전체를 함께 올릴지, pnpm override로 고정할지 spec에서 정한다. 사용자: 전체를 올려도 문제 없으면 올림, 알려진 취약점(npm audit, GitHub advisories)을 확인한다.
2. **OAuth 서버**:
   - 인가와 동의 화면(Vue): Allot에 로그인한 뒤 범위를 고른다.
   - 토큰: 발급, 갱신(새 토큰으로 교체, 재사용 허용 시간 0), 폐기. 저장은 해시로만 한다.
   - 메타데이터: Protected Resource Metadata와 Authorization Server Metadata를 루트 `/.well-known/`에 둔다.
   - 클라이언트 등록: CIMD와 동적 등록(DCR)을 둘 다 연다. ChatGPT와 Claude는 CIMD를, Gemini는 DCR만 쓴다(조사).
   - 실패 제한은 키와 같다.
3. **`/mcp`와 OAuth 토큰**:
   - `/mcp`가 API 키와 OAuth 토큰을 둘 다 받는다. `/api/mcp`는 키만 받는다.
   - 401 응답에는 `resource_metadata`를 담는다.
   - 토큰은 `/mcp`용으로 발급된 것(audience)만 받는다.
   - 매 호출마다 그 연결이 아직 살아 있는지 확인해서, 끊은 즉시 401이 되게 한다. Better Auth의 JWT 토큰은 폐기해도 만료 전까지 통하기 때문이다(조사).
4. **연결된 앱**:
   - 설정 › AI·연동: 앱 이름, 범위, 연결 날짜, 마지막 사용을 보고 끊는다.
   - 관리 › 로그인 방식: '외부 앱 연결(OAuth)' 스위치를 둔다. 기본은 꺼짐이고, env로도 켠다.
5. **스킬 7개**: 공통 형식(agentskills.io의 `SKILL.md`, 규격 필드만)으로 한 벌을 쓴다. 지금 MCP 도구로 못 하는 일(예: 잔액 기록을 AI가 바꿀 수 없는 것)은 해당 화면으로 안내한다.
6. **설치 묶음**:
   - `.claude-plugin/`: 마켓플레이스와 플러그인. 서버 주소는 설치할 때 `userConfig`로 받고, 인증은 OAuth가 기본이다. API 키를 넣으면 키로 붙는다.
   - Codex 플러그인 묶음.
   - Gemini CLI 확장(`gemini-extension.json`, `GEMINI.md`, 스킬).
   - claude.ai용 스킬 ZIP을 만드는 스크립트.
   - 설치는 모두 이 저장소 주소로 한다. 공식 디렉터리·갤러리에는 올리지 않는다(사용자: "공식 디렉터리는 그냥 패스하자. 그냥 우리 저장소 쓰는 거로.").
7. **MCP 서버 안내문**: 서버의 `instructions`를 쓴다. ChatGPT 웹과 Gemini 앱은 묶음 파일을 읽지 않으므로, 이 안내문으로 기본 흐름을 전한다. 앞 512자가 중요하다(조사).
8. **패스키**:
   - `@better-auth/passkey`를 로그인 방식의 하나로 둔다. 다른 방식과 같은 켜기·끄기와 정책을 따른다.
   - `rpID`는 `BETTER_AUTH_URL`의 도메인으로 한다.
   - IP 주소로 여는 LAN 설치에서는 쓸 수 없다고 문서에 적는다.
9. **문서**:
   - README "AI 연결": 세 AI별 연결 방법, 요금제 제약, 공개 HTTPS 요건(LAN 전용이면 Claude Code와 API 키만), Anthropic·OpenAI가 접속하는 IP.
   - CHANGELOG.
10. **검사**:
    - :15174에서 가짜 클라이언트로 OAuth 흐름 전체를 돈다: 등록(CIMD·DCR) → 인가 → 동의 → 토큰 → `/mcp` 호출 → 갱신 → 끊기 → 401.
    - 함께 확인할 것: 범위별 도구 목록, 사용자 격리, `/api/mcp` 키 회귀, 패스키 등록·로그인(가상 인증기 E2E).
    - 실제 AI 클라이언트로 연결하는 확인은 사용자가 rc를 사용자 서버에 올린 뒤 한다(화면 확인과 같은 방식).
      - Claude: claude.ai·휴대폰·Claude Code
      - ChatGPT: 웹(요금제가 허용하는 범위)·Codex
      - Gemini: CLI

- **server**:
  - `server/auth.ts`: 플러그인.
  - 루트 경로 `/mcp`와 `/.well-known/*`(`server/app.ts`; 지금은 API가 `/api` 아래에만 있다).
  - `server/mcp/index.ts`: 인증.
  - 스키마와 마이그레이션: OAuth 클라이언트·토큰·동의·리소스·jwks, passkey.
  - 로그인 방식 설정(`methodOf` 등).
- **화면**: 동의 화면, 설정 › AI·연동(연결된 앱, MCP 주소 `/mcp`), 관리 › 로그인 방식(외부 앱 연결, 패스키), 계정 화면(패스키 등록).
- **개발 서버**: Vite 프록시에 `/mcp`, `/.well-known`을 더한다.
- **저장소**: `.claude-plugin/`, Codex·Gemini 묶음, `skills/`, README, CHANGELOG.
- **기존 동작**: API 키, MCP 도구, 쓰기 제안의 동작은 바뀌지 않는다. `/api/mcp`도 그대로다.

## 제약
- 개인 금융 데이터라 보안이 기능보다 먼저다.
  - PKCE(S256)는 필수다. 돌아갈 주소는 정확히 같아야 한다. Claude Code의 localhost 콜백은 포트만 다를 수 있다.
  - 동의 없이 발급하지 않는다. 관리자도 다른 사용자의 연결을 만들지 못한다.
  - 갱신 토큰은 쓸 때마다 새 것으로 바꾼다(refresh token rotation, 사용자 승인). Google은 바꾸지 않는 갱신 토큰을 권하지만, 보안 쪽을 따른다. 그래서 Gemini에서 문제가 생기면 기록하고, 바꾸지는 않는다.
- **RLS 예외**: OAuth·passkey 테이블은 사용자를 알기 전에 읽히므로 행 수준 보안(RLS)을 걸 수 없다. 지금의 Better Auth 테이블(`auth-schema.ts`)처럼 RLS 예외로 두고, 앱 조건으로 사용자를 나눈다. 초안의 "RLS"를 이렇게 바꾼다(조사).
- **공개 HTTPS**: 원격 커넥터(claude.ai·휴대폰·ChatGPT·Gemini 앱)는 그 회사 쪽에서 Allot 서버로 접속한다. 사용자의 설치는 이미 공개 HTTPS 주소가 있다(사용자). LAN 전용 설치는 Claude Code·Codex·Gemini CLI만, 그것도 API 키로만 쓸 수 있다. Claude Code는 http 주소로는 OAuth를 보내지 않는다(조사).
- **요금제**: ChatGPT에서 쓰기 도구는 Business·Enterprise/Edu 요금제에서만 된다. Pro는 읽기만 되고, Plus는 확인하지 못했다(조사). 문서에 적는다.
- **입력 거부·새 제한**: 예전 입력을 거부하거나 새 제한을 거는 변경은 spec에 적고 승인받는다(AGENTS.md).
- **공개 저장소**: 실제 데이터, 계정, 금액은 어디에도 넣지 않는다. 사용자의 서버 주소도 문서·예시·시험에 넣지 않고 `<your-host>`로 쓴다(PM 판단).
- **실제 서버**: 사용자의 서버에는 실제 데이터가 있다. 자동 검사는 그곳에 돌리지 않는다. 실제 클라이언트 연결 확인은 사용자가 한다.

- **Allot이 직접 인가 서버가 된다**(사용자 OK).
  - 대안: 외부 IdP에 맡기기. 그러면 범위와 키 주인 규칙을 Allot이 정할 수 없고, 비밀번호만 쓰는 설치에서는 쓸 수 없다.
- **클라이언트 등록은 CIMD와 DCR을 둘 다 연다.**
  - 대안: CIMD만(규격 권장, DCR은 2026-07-28 판에서 폐지 예정). 그러면 Gemini 앱·CLI가 붙지 못한다.
  - DCR은 누구나 클라이언트를 등록할 수 있다. 하지만 외부 앱 연결이 기본으로 꺼져 있고, 사용자 동의 없이는 토큰이 나가지 않는다.
- **`/mcp`는 키와 OAuth를 둘 다 받고, `/api/mcp`는 키만 받는다.**
  - 대안: 둘 다 OAuth를 받기. 그러면 토큰의 대상(audience)이 둘이 되어 규격의 "자기에게 발급된 토큰만" 검사가 흐려진다.
- **스킬은 지금 MCP 도구만 쓴다**(사용자 승인). 도구를 늘리거나 바꾸는 일은 하지 않는다(하지 않을 것). 스킬이 하려는 일에 도구가 없으면, 그 화면으로 안내하는 문장을 넣는다. 나중 버전에서 도구가 바뀌면 그 버전에서 스킬도 고친다(사용자: "기능이 업데이트 되면 스킬도 업데이트").
- **0.1.10의 실제 사용 수정 8항목은 이 intent에 넣지 않는다.** 사용자가 "OAuth와 플러그인 이후"로 정했다.
- **AWS 같은 공개 서비스 운영은 이 버전에서 뺀다.** 0.1.10까지 한 뒤 따로 검토한다(사용자). 검토할 가치는 있다(조사). 다만 공개 서비스로 가려면 이 버전 밖의 일이 많다.
  - 앱이 바뀌어야 하는 것: 가입, 메일(확인·비밀번호 재설정), 본인 탈퇴·내보내기, 약관·개인정보 동의, 여러 인스턴스 대응(지금 제한·작업은 메모리), 운영자 MFA·접근 기록, 보존 기간.
  - 법적 의무(개인정보 보호법): 처리방침, 보호책임자, 안전조치, 72시간 통지.
  - 비용은 서울 리전 월 약 15~75달러.

  그래서 `.loctx/ROADMAP.local.md`에 검토 항목으로 남기고, 사용자와 정한다.

## 하지 않을 것
- **공식 디렉터리·갤러리 등록** (사용자: "공식 디렉터리는 그냥 패스하자. 그냥 우리 저장소 쓰는 거로."; 조사):
  - Anthropic 커넥터 디렉터리: 사용자마다 주소가 다른 서버는 'URL 패턴' 등록이 필요하다. 그런데 그런 등록은 Anthropic이 정해 주는 Verified 표시가 있어야만 공개된다.
  - Claude 공식 플러그인 마켓플레이스: 제출을 받지 않는다(파트너 경로만).
  - ChatGPT 디렉터리: 플러그인 하나에 고정 주소 하나만 받고, 신원·도메인 확인을 거친다.

  셋 다 하나의 공개 서비스 주소가 있어야 맞는다. Gemini CLI 갤러리(저장소 주제 태그로 자동 등록)도 하지 않는다.
- Gemini 앱(사용자 지정 앱)의 연결 확인(지역 제한). 표준대로 맞추는 데서 그친다.
- AWS 등 공개 서비스 운영과 그 준비(위).
- MCP 도구의 추가나 변경(0.1.10 항목 3·8의 도구 설명 수정 포함).
- Allot 자체 로그인의 다른 변경(패스키 추가 밖).
