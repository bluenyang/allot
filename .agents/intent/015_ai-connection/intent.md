## 문제
사용자 말:
> 각 기능을 mcp로 붙여서 AI로 추가 가능하게. market place와 plugin 설치가 최종 목표 (2026-11-23, 0.1.7 범위를 정할 때)
> 0.1.7 바로 다음 (Recommended) (2026-11-23, 플러그인 버전 순서)
> OAuth는 플러그인 바로 다음으로. (2026-11-25)
> 합치면 안되나 → 플러그인+OAuth를 0.1.9 하나로 (Recommended) (2026-11-25)
> 응. 실제 사용에서 결함이 보이는데, 이거는 0.1.10에서 해야겠어. 얼른해보자. … (OAuth와 플러그인 이후 수정) → 0.1.9 intent 지금 시작 (Recommended) (2026-11-25)

지금(0.1.8)은 AI가 Allot에 닿는 길이 API 키 하나뿐이다.
- 사용자가 설정 › AI·연동에서 키를 만들고, 그 키를 클라이언트에 직접 붙여 넣는다(`claude mcp add … --header "Authorization: Bearer <key>"`).
- claude.ai와 휴대폰 앱의 원격 커넥터는 OAuth만 받는다. 그래서 그 둘에서는 Allot을 쓸 수 없다(README "MCP로 AI 연결").
- Claude Code에서도 설치할 것이 없다. 사용자가 명령을 손으로 적어야 한다.
- 설정 › AI·연동의 '연결된 앱 관리'는 0.1.7부터 "준비 중"으로 남아 있다.

## 바라는 결과
- **OAuth로 연결**: claude.ai와 휴대폰 앱에서 Allot 주소만 넣고 OAuth로 연결한다. 사용자는 Allot 로그인과 동의 화면을 거치고, 키를 붙여 넣지 않는다.
- **플러그인 설치**: Claude Code에서 마켓플레이스를 더하고 플러그인을 설치하면 Allot MCP 서버가 붙는다.
- **연결된 앱 관리**: 설정 › AI·연동에서 연결된 앱을 보고 끊는다. '준비 중' 표시는 없어진다.
- **권한은 키와 같다**: OAuth로 연결해도 읽기 또는 쓰기 제안, 확인 방식, 키 주인의 데이터만 보는 범위가 API 키와 똑같다. 기존 API 키는 그대로 쓸 수 있다.

## 계획
(PM의 순서, 각 단계는 spec의 W-n이 됨)
1. **조사** (spec 전에, PM과 위임 조사):
   - MCP 인가 규격의 지금 판: Protected Resource Metadata, Authorization Server Metadata, 클라이언트 등록 방식(동적 등록 또는 Client ID Metadata Document), PKCE.
   - claude.ai와 휴대폰 앱 원격 커넥터가 실제로 요구하는 것.
   - Claude Code 플러그인과 마켓플레이스의 지금 형식(`.claude-plugin/`, MCP 설정, 사용자 설정값).
   - Better Auth 1.7의 OAuth 제공자 플러그인이 맞는지(AGENTS.md: 로그인·접근 기능은 `server/auth.ts`의 Better Auth 플러그인).

   조사 결과는 spec의 해석과 설계에 넣는다.
2. **OAuth 서버**: 인가와 동의 화면(Allot 로그인 뒤 범위를 고름), 토큰 발급·갱신·폐기, 클라이언트 등록, 메타데이터. 토큰은 해시로만 저장하고 만료가 있다. 실패 제한은 키와 같다.
3. **MCP 엔드포인트**: `POST /api/mcp`가 OAuth 액세스 토큰도 받는다. 범위(읽기, 쓰기 제안, 확인 방식)는 키와 같은 규칙으로 도구 목록과 권한을 정한다. API 키 경로는 바꾸지 않는다.
4. **연결된 앱**: 설정 › AI·연동에서 앱 이름, 범위, 연결 날짜, 마지막 사용을 보고 끊는다(토큰 폐기). 관리 화면에서 OAuth를 끄는 스위치를 둔다(기본 값은 열린 질문).
5. **플러그인과 마켓플레이스**: 이 저장소에 마켓플레이스 목록과 플러그인(Allot MCP 서버 설정)을 둔다. 설치한 뒤 서버 주소와 인증을 어떻게 받는지는 열린 질문 1이다.
6. **문서**: README "MCP로 AI 연결"(claude.ai, 휴대폰, Claude Code 플러그인), 운영 배포의 공개 주소 요건, CHANGELOG.
7. **검사**: OAuth 흐름 전체(등록 → 인가 → 동의 → 토큰 → MCP 호출 → 갱신 → 폐기)를 가짜 클라이언트로 :15174에서 돌린다. 범위별 도구 목록, 사용자 격리, 끊은 뒤 401, API 키 회귀, 플러그인 설치를 확인한다.

## 영향 범위
- **server**: `server/auth.ts`(플러그인), 새 OAuth 경로, `server/mcp/index.ts`(인증), 스키마와 마이그레이션(OAuth 클라이언트·토큰·동의 테이블, RLS).
- **화면**: 동의 화면, 설정 › AI·연동(연결된 앱), 관리 › 로그인 방식(OAuth 스위치).
- **저장소**: `.claude-plugin/`(마켓플레이스), 플러그인 폴더, README, CHANGELOG.
- **기존 동작**: API 키, MCP 도구, 쓰기 제안의 동작은 바뀌지 않는다.

## 제약
- 개인 금융 데이터라 보안이 기능보다 먼저다. 토큰은 해시로 저장한다. PKCE는 필수다. 돌아갈 주소(redirect URI)는 정확히 같아야 한다. 동의 없이 발급하지 않는다. 관리자도 다른 사용자의 연결을 대신 만들지 못한다.
- 원격 커넥터는 Anthropic 쪽에서 Allot 서버로 접속한다. 그래서 claude.ai와 휴대폰 연결에는 인터넷에서 닿는 HTTPS 주소가 필요하다. LAN 전용 설치는 Claude Code 플러그인(로컬)만 쓸 수 있다. 문서에 그렇게 적는다.
- 예전 입력을 거부하거나 새 제한을 거는 변경(새 검증, 범위 제한)은 spec에 적고 승인받는다(AGENTS.md).
- 공개 저장소라 실제 데이터, 계정, 금액은 어디에도 넣지 않는다.

## 열린 질문
1. 플러그인의 인증은 무엇으로 할까요?
   - (a) OAuth: Claude Code가 OAuth를 처리하므로 키를 붙여 넣지 않는다.
   - (b) API 키: 설치할 때 키를 넣는다.
   - (c) 둘 다: 기본은 OAuth, 키는 대안. **PM 안: (c).**
2. 플러그인에 무엇을 담을까요?
   - (a) MCP 서버 설정만.
   - (b) MCP와 함께 자주 쓰는 일을 묶은 스킬 몇 개. 예를 들면 "이번 달 점검", "받은 월급 적기", "지출 추가".
   - **PM 안: (b), 스킬 2~3개.** 스킬은 도구 설명을 반복하지 않고, 흐름만 묶는다.
3. 마켓플레이스는 어디에 둘까요?
   - (a) 이 저장소: `bluenyang/allot`을 마켓플레이스로 더하고, 버전을 앱과 함께 올린다.
   - (b) 별도 저장소.
   - **PM 안: (a).**
4. OAuth로 쓰기 제안까지 허용할까요?
   - (a) 동의 화면에서 키처럼 읽기 또는 쓰기 제안과 확인 방식을 고른다.
   - (b) OAuth는 읽기만.
   - **PM 안: (a).** 쓰기 제안도 적용 전에 확인을 거치는 지금 구조가 그대로이기 때문이다.
5. OAuth 연결(외부 앱 연결)은 처음에 켜 둘까요, 꺼 둘까요?
   - (a) 꺼 둔다: 관리자가 관리 화면이나 env로 켠다.
   - (b) 켜 둔다.
   - **PM 안: (a).** 자체 호스팅이라 공개 주소가 없는 설치가 많고, 지금의 "만료 없는 키는 기본으로 막음"과도 결이 같다.

## 질의서 기록
—

### 에이전트가 정한 것
- **OAuth는 Allot이 직접 인가 서버가 된다.** 대안은 외부 IdP(로그인에 쓰는 OIDC)에 맡기는 것이다. 그러면 범위(읽기/쓰기 제안/확인 방식)와 키 주인 규칙을 Allot이 정할 수 없고, 비밀번호만 쓰는 설치에서는 쓸 수 없다.
- **0.1.10의 실제 사용 수정 8항목과 1~3번 원인 확인은 이 intent에 넣지 않는다.** 사용자가 "OAuth와 플러그인 이후"로 정했다. 원인 확인(읽기 전용)은 0.1.10 intent 자료로만 남긴다.

## 하지 않을 것
- ChatGPT 같은 다른 AI 클라이언트에 맞춘 작업. 표준 OAuth와 MCP를 따르므로 될 수는 있지만, 확인하고 문서에 적는 것은 Claude 클라이언트까지만 한다.
- 패스키 로그인, Allot 자체 로그인의 변경.
- MCP 도구의 추가나 변경(0.1.10 항목 3·8의 도구 설명 수정 포함).
- 플러그인 공식 디렉터리 등록(마켓플레이스는 이 저장소까지만).
