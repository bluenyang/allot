origin `bluenyang/allot`은 공개 저장소다. 지금 저장소에는 다음이 있다.
- git 이력의 `src/data/seed.ts`(커밋 faaf7fd, 2665ca6, 2ad9d60): 실제 재무 데이터 전체.
- 현재 코드와 화면 문구: 은행·상품 이름이 분배 계산(`src/lib/calc.ts`), 구간 필드(`cheongyak`, `cma`, `future`, `reserve`), 설정(`roundUnit`), 화면 안내문에 하드코딩돼 있다. 개인 수치와 사정(연봉, 대출 금리·이자, 실수령 예시, CMA 목표액, 카드 사용 방식, 지원금 유형)도 안내문에 있다.

## 바라는 결과
- 공개해도 되는 저장소: 현재 트리와 **모든 git 이력**에 실제 데이터 파일, 개인 수치·사정, 은행·상품 이름이 없다.
- 앱은 지금처럼 동작하되, 통장·분배 구조를 사용자가 데이터로 정한다(코드에 은행 이름이 없다). 사용자의 실제 구조는 로컬 시드(`.loctx/scripts/seed-data.ts`, `.sql`)와 DB에만 있다.
- 정리가 끝나고 감사까지 마친 뒤 origin에 푸시한다.

## 계획
1. 분배 구조를 일반화한다 (에이전트 해석, 정확한 설계는 spec):
   - **분배 대상** 목록을 데이터로 둔다. 각 대상은 이름과 종류를 가진다. 종류: 생활비 합계 / 구독 필요 이체액 / 구간별 고정 금액 / 나머지 전부(하나만).
   - 구간(phase)의 고정 금액은 대상별로 저장한다(지금의 청약·CMA·적금·잔류 열 대신).
   - "ISA 분배"는 "나머지 분배"로 일반화한다. 설정 `roundUnit`는 "구독 이체 올림 단위"로 이름을 바꾼다.
   - DB 마이그레이션으로 기존 데이터를 새 구조로 옮긴다. 로컬 시드(`.ts`, `.sql`)도 새 구조로 바꾼다.
2. 화면 문구에서 개인 수치·사정과 은행 이름을 지우고 일반 설명으로 바꾼다.
3. 테스트(API 검사, E2E, 대비)를 새 구조에 맞추고 다시 돌린다.
4. 리뷰 → test → 머지 → 감사.
5. 이력 정리 (2026-11-10 사용자 결정으로 변경, spec 003 approvals `kind: change`): 백업 번들을 만든 뒤 **새 .git**에서 현재의 깨끗한 트리를 커밋 하나로 시작한다. 옛 이력은 로컬 번들에만 두고, 기록(intent·spec·감사)의 rev 참조는 그 번들에서 따라갈 수 있게 한다.
6. 새 이력을 다시 검사한다(아래 "제약"의 금지어가 없음, `src/data/seed.ts` 없음).
7. `v0.1.0-rc.3` 태그. 사용자에게 최종 확인을 받은 뒤 origin에 `master`와 태그를 푸시한다.

## 제약
- 새 .git은 `master`와 태그(`v0.1.0-rc.1`)를 포함한 옛 이력을 공개 저장소에서 뺀다. 작업 전 전체 백업 번들을 `.loctx/backup/`(로컬 전용)에 둔다. 백업에는 옛 이력이 그대로 있으므로 공개하지 않는다.
- 공개 저장소의 커밋 id는 옛 이력과 이어지지 않는다. Syncthing 등 다른 사본에는 옛 이력이 남을 수 있다(사용자 관리).
- 금지어 목록(은행·상품 이름, 개인 수치)은 spec에서 확정한다. 금지어 자체를 저장소에 커밋하지 않는다(목록은 `.loctx/`에만 둔다).
- (변경 전 방식의 도구) `git filter-repo`는 사용자가 설치했다. 새 .git 방식에서는 쓰지 않는다.
- 푸시는 사용자의 최종 확인 뒤에 한다.
